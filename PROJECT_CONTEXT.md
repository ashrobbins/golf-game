# Beating Bogey — Project Context

A handoff doc for picking this project up in a fresh chat. Paste this in, or point a new session at this file.

## What this is

A golf draft-and-simulate game, inspired by [38-0](https://38-0.app): draft a bag of 18 real golfers (one per hole) via a wheel-spin mechanic, then simulate a round hole-by-hole and chase a bogey-free 18. Original design doc: `golf-draft-game-plan.md` (repo root) — read that for the full original concept, including deferred future ideas (Tour Season, leaderboards, Supabase backend).

**Current scope**: client-side only MVP. No backend, no accounts, no persistence between sessions — matches the plan's explicit MVP-minus-Supabase scope that was agreed early on.

## Architecture

**Pure logic is fully decoupled from React/UI**, under `src/game/`:
- `src/game/draft/engine.ts` — pure draft state machine (spin wheel → draw 3 golfers → pick one → repeat). Rules: countries stay on the wheel until either 3 picks from them or their remaining bench drops below 3; picked golfers never reappear; unpicked-but-offered golfers return to the bench.
- `src/game/simulation/engine.ts` — given the completed 18-hole bag, resolves an outcome tier per hole (`hole_in_one | eagle | birdie | par | bogey_plus`) from `public/content/odds-config.json`. Archetype fit is now a continuous 0–1 blend (`src/game/simulation/affinity.ts` — `golferHoleFitWeight`, via a ranked best-to-worst affinity table per archetype), lerped between the `matched`/`unmatched` distributions rather than a hard either/or switch. `src/game/simulation/skill.ts`'s `applySkillShift` (`legend/elite/solid/journeyman`) is layered on top and now itself scales with that same fit weight — a legend on a matched hole gets close to the design brief's ~95% par-or-better target, but the same legend stranded on a poor-fit hole gets much less benefit. `affinity.ts` also exports `bestFitArchetype`, used purely for display (which of a golfer's archetypes to show as "theirs" on a given hole — see the draft roster below), not for the odds math.
- `src/game/simulation/commentary.ts` — template-based, golf-accurate flavor text per hole outcome (distinguishes "tee shot" vs "approach" by par, and "matched" vs "unmatched" archetype-fit framing for expected-vs-upset narration).
- `src/game/rng.ts` — seedable `mulberry32` RNG used in tests for determinism; production code defaults to `Math.random`.

**Content is static JSON**, fetched at runtime from `public/content/` (designed so it can later point at an S3/CDN URL with zero reshaping — see `src/content/contentSource.ts`):
- `countries.json` — 19 countries, 124 golfers (was 23/141-with-a-duplicate; see session #12: 5 thin countries removed, USA/England/Australia beefed up, plus a synthetic 19th "Others" country — id `others`, isoCode `OTH` deliberately doesn't match either flag-emoji pattern in `flag.ts` so it falls through to the white-flag default — for real players who don't cleanly fit one of the curated nations). Each golfer has 1–2 `archetypes` and an optional `skill` tier (defaults to `solid` if omitted). A `Country` can also carry an optional `repeatCap` overriding the default max-picks-per-country (see below) — currently only set on USA and England.
- `courses.json` — Augusta National (par 72, verified against the 2024 Masters card) and Carnoustie (par 71). **Known discrepancy**: the original design doc assumed Carnoustie was 4 par-3/11 par-4/3 par-5; the real official club scorecard is actually 3 par-3/13 par-4/2 par-5 (still par 71). Used the real numbers; the doc's assumption was wrong.
- `odds-config.json` — per-par-type `matched`/`unmatched` outcome distributions. "Archetype fit shifts odds, never guarantees" is enforced as a literal data property (checked in tests): every `matched` row keeps a non-zero `bogey_plus` floor, every `unmatched` row keeps a non-zero birdie-or-better floor, and `hole_in_one` is baked to 0 for par 4/5.

**State/routing**: `src/state/GameProvider.tsx` + `GameContext.ts` + `useGame.ts`. No react-router — a `View` enum (`'home' | 'course-info' | 'draft' | 'results'`) drives which page renders in `App.tsx`. Flow: pick a course on Home → `course-info` (new course preview page, added this session) → click "Let's Go" → `draft` (auto-spins hole 1 immediately) → after 18 picks → `results` (reveal sequence, then final scorecard + share + play again).

**Components** are organized by feature under `src/components/`: `draft/`, `picker/` (country/golfer spinners), `scorecard/`, `course/` (preview-page table), `share/`, `ui/` (shared `Button`, `ArchetypeBadge`), `nav/`, `home/`.

- `GolferCard` (`src/components/draft/GolferCard.tsx`) is only ever rendered inside `GolferReels` (one call site). Surname is the larger/bolder line, first name smaller/muted (deliberately swapped from an earlier version). Takes an optional `onClick` — when set, the whole card is a keyboard-accessible selection control (role="button", Enter/Space handled), not just the Select button below it; `GolferReels` only wires this up once a reel has settled (`allSettled`), so mid-spin filler items in the strip aren't clickable.
- `DraftRoster` (`src/components/draft/DraftRoster.tsx`, the "Your bag" list) now takes `holes: Hole[]` as a prop (added so it can look up each pick's hole archetype). Each row: hole number, country flag, golfer name, then `PlayerArchetype / HoleArchetype` badges (`bestFitArchetype` picks whichever of the golfer's archetypes fits that specific hole best — not just their first-listed one). Row is `flex-wrap: wrap`; the archetype pair has **no explicit alignment** — on a wide row it ends up flush right anyway because `.golferName`'s `flex-grow` eats all remaining space on that line, but deliberately has no `margin-left: auto`, so once it wraps onto its own line on narrow viewports it falls flush left instead of an auto-margin dragging it back to the right edge. If you touch this again, don't reflexively add `margin-left: auto` back to "fix" desktop alignment — it isn't needed there and breaks the wrapped mobile case.

## Design system

- Colors/tokens in `src/index.css` (`:root` + a `prefers-color-scheme: dark` block): `--accent` (indigo `#5b4fe8`), `--surface`, `--shadow`, tier colors (`--tier-gold/green/grey/red` for outcome-tier coloring), and per-archetype colors (`--archetype-long-hitter/precision-iron/short-game/scrambler/closer` — `closer` used to deliberately reuse `--tier-gold`, but that made it read too close to scrambler's orange; it now has its own token, a rose/crimson, distinct from every other archetype hue).
- `Button` (`src/components/ui/Button.tsx`): `primary` (solid indigo) / `secondary` (outlined) variants, matching a reference screenshot the user provided. Applied to: Let's Go / Draft / Play again (primary), Select / Selected-toggle / Share / Skip (secondary, "Selected" flips to primary once picked).
- `ArchetypeBadge` (`src/components/ui/ArchetypeBadge.tsx`): shared colored-dot + label badge, used on the course preview table, the draft page's hole header, golfer cards, and the draft roster — extracted specifically so those places can't visually drift apart. Deliberately `display: inline-block` (not flex) so long labels (e.g. "SHORT GAME WIZARD") can wrap onto a second line in narrow mobile cards instead of overflowing. Takes two independent optional props: `size` (`'default' | 'compact'`, font-size only) and `dot` (boolean, the leading colour dot, default `true`) — kept separate because different call sites need different combinations (golfer cards want compact+no-dot; the draft roster wants default-size+no-dot).
- **Legend-tier indicator**: no separate badge component (a `LegendBadge` icon was tried and explicitly rejected as too loud, then deleted). Legend golfers now get a subtle `--tier-gold` treatment on the container that actually reads as "the card" — `GolferReels`' `.column` (the bordered/shadowed box holding the card *and* its Select button) on the picker screen, and an inset `box-shadow` on the row (not a real border, to avoid shifting column alignment) in the draft roster. Don't put this back on `GolferCard.tsx` itself — that component is only the inner content and doesn't visually read as "the card" to a user (this was corrected once already: the border first went on `GolferCard`, which only wrapped the name/archetype text, not the Select button below it).
- Course cards (home page) use **gradient placeholders**, not real photography — the user was asked and explicitly chose this over sourcing stock photos, due to licensing risk on real course photography. Swapping to real images later is a one-line change in `CourseCard.tsx`'s color lookup.
- Nav bar: simple white bar, logo/wordmark is the only link, calls `playAgain()` (abandons any in-progress round back to Home — that's intentional, not yet gated behind a confirmation).

## Testing

Vitest, 37 tests, all on pure logic (no component/UI tests — UI has been verified manually via the Browser preview tool every session, not automated):
- `src/game/draft/engine.test.ts` — repeat-cap, bench-exhaustion, no-duplicates, full-18-hole invariants across ~200 seeds.
- `src/game/simulation/engine.test.ts` — real odds-config content validation (sums to 1, floors hold, aces are par-3-only), frequency tests, fixture tests for streak/total derivation.
- `src/game/simulation/skill.test.ts` — skill shift never guarantees, monotonic legend > elite > solid > journeyman, never touches eagle/ace tiers.
- `src/game/simulation/affinity.test.ts` — exact match always scores 1, mismatches always score below 1, ranked ordering per archetype, second-archetype bonus never lets a weak generalist beat a matching specialist, `bestFitArchetype` picks the right one regardless of listed order.
- `src/game/simulation/commentary.test.ts` — no unfilled template placeholders across every tier/fit/par combo, correct surname extraction, tee-shot-vs-approach phrasing.

## Things a future session should know / watch for

- **Country capacity invariant**: `assertWheelHasCapacity()` in the draft engine throws loudly at content-load time if total draft capacity (Σ `min(country.repeatCap ?? REPEAT_CAP, bench size)` per country) can't fill 18 holes. Keep this in mind if trimming/editing `countries.json`.
- **Per-country repeat cap**: `Country.repeatCap` (optional, `content/types.ts`) overrides the default `REPEAT_CAP` (3) for that one country — currently only USA and England are set to 5, since their benches got deliberately loaded up with marquee names. Threaded through as `DraftState.countryRepeatCaps` (built once in `createInitialDraftState`) rather than a bare constant, since `applyPick`'s eligibility check needs it per-country. The wheel-spin itself is untouched (still uniform-random among whichever countries are active), so raising a cap doesn't change that country's odds of being spun, only how long it stays eligible.
- **Reduced motion**: the spinners (`Reel.tsx`) and confetti respect `prefers-reduced-motion`.
- **No dead code policy has been followed carefully** — e.g. the manual hole-1 "spin" button was fully removed (not just hidden) once auto-spin covered that case.
- If asked to source real course photography for the home page cards: this was explicitly deferred due to licensing risk, not forgotten. Revisit only with either user-supplied images or a verifiably-licensed source.
- Northern Ireland has no officially recognized Unicode flag emoji sequence (unlike England/Scotland/Wales, which do), so `isoToFlagEmoji()` (`src/components/picker/flag.ts`) still falls back to a plain black flag for it — but nothing actually calls that function for `GB-NIR` anymore. `CountryFlag` (`src/components/picker/CountryFlag.tsx`) wraps it and special-cases `GB-NIR` to render a real image of the Ulster Banner (`nir-flag.png`, user-supplied) instead, sized to `1em` so it drops into the same slot the emoji occupied. Named `CountryFlag`, not `Flag`, specifically to avoid a case-only filename collision with `flag.ts` on macOS's case-insensitive filesystem (that collision broke `tsc -b` the first time). If another subdivision ever needs the same treatment, extend `CountryFlag`'s special-case check rather than duplicating it at each call site — it's already used from both `CountryPicker` and `DraftRoster`.
- `GolferCard` has exactly one call site (`GolferReels`). Before adding any second usage, re-check whether `onClick`-driven selection and the "whole card is the visual unit" assumption baked into the legend border placement (see above) still make sense there — they were written with only that one context in mind.
